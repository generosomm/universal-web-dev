# S01: One-page site a traveller can use to choose a room and send a booking email
Status: Implemented (owner review of sample content pending)
Goal: a stranger understands Saltrum, compares rooms, checks the lighthouse walk and emails a booking request.
Scope: one page, 404 page, tide window, booking by email; excludes payment, availability and analytics.
Depends on: none
Acceptance:
- [x] First screen names the place in an h1, says what it is in one sentence, and offers one action.
- [x] Four rooms with bed, view and sample price; each has its own booking email.
- [x] A chosen date shows that day's low-tide windows; windows crossing midnight stay on that day.
- [x] The tide model is labelled as a sample, not for navigation.
- [x] No fake checkout: every booking action is a mailto link; the form posts nowhere.
- [x] Without script, all content shows and the tide panel gives a plain answer.
- [x] No horizontal scroll at 1440 and 375 px; standalone tap targets at least 24 px.

## Routing trial findings
Bugs found by the checks and fixed: an `export` in a classic script disabled every feature; a CSS rule stretched the main button over its folder; an off-screen card and a scaling photo caused horizontal scroll; tide windows across midnight read as the wrong day; one card failed contrast.

What the trial showed about Universal Web Dev:
1. Skill text read for this landing page: wrapper 5 KB, bootstrap 6 KB, readiness 6 KB, Taste 38 KB, Impeccable 12 KB (partly) + polish 7 KB + craft floor 6 KB: about 80 KB. `ponytail` and `verification-before-completion` (7 KB) are routed too but were not read in this trial. Taste is the bulk and was worth it for a new page.
2. Impeccable `critique` alone is 49 KB; `polish` (7 KB) is the right final pass unless a critique is requested.
3. `brainstorming` and `writing-plans` (20 KB together) added nothing to a fixed written brief and were not loaded.
4. Taste and Impeccable disagree on display size and entrance motion; Impeccable's own floor defers to the committed world, so the direction skill wins.
5. A skill's checking script can fail for environmental reasons; its documented fallback worked and the record says the check did not run.
