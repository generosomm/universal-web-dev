# Required Impeccable runtime for UI work

The full Impeccable skill, including its launchers, VERSION and engine checksum manifest, ships in core and in the default all-skills installation. Do not substitute a guidance-only installation or skip setup by choice. Backend-only, copy-only and non-UI work do not need a design runtime.

1. Resolve the actual installed Impeccable skill folder and read its SKILL.md. From the user's project directory, run `<impeccable-skill-dir>/scripts/impeccable context` once per project session, or its `scripts/impeccable.cmd context` on Windows. Follow its applicable reference instructions and read craft-floor immediately before editing UI. Preserve the existing design unless a redesign was requested.
2. The upstream launcher can fetch its VERSION-pinned engine on first use and checks downloaded binaries against the checksum manifest shipped in the commit-pinned skill. This is runtime setup, separate from copying skill files. Respect host permissions and explicit offline/network restrictions. Never disable checksum verification, substitute an unpinned latest binary, or set an executable/download override just to make setup pass.
3. Installation copies upstream scripts but never executes them. Ordinary UI-task authorization covers running required context setup within host permissions. Context success does not mean the detector, live browser mode or a design review ran. Execute the selected command through the installed skill's documented workflow and report its actual result.
4. If the launcher is refused, unavailable or fails, state that context did not run before another tool call. Read existing PRODUCT.md and DESIGN.md and use Impeccable's documented degraded workflow within the task's scope. Report runtime setup as incomplete; manual review is not full runtime verification. Retry only after addressing the concrete cause, not in a loop. Do not block unrelated implementation or claim complete Impeccable coverage.

Live mode needs its documented browser support. Commands, hooks, shortcuts, context initialization and drift repair remain available, but run only when requested or required by the applicable upstream workflow. Including every capability does not authorize global hooks, unrelated configuration changes, or all commands on every task. Keep existing customizations and load only task-relevant references.
