# A distinctive, usable design

Use when establishing a visual direction, not for every existing-page edit. The selected direction skill supplies its technique; this file sets the outcome. Existing brand, accessibility needs and accepted design win over novelty.

1. Identify what is specific about the audience, content and product. Inspect a small relevant set of real category references when browsing is available. Record what to learn and what to avoid, with links; never claim research you could not do. User references can be enough. Avoid an open-ended inspiration search.
2. Choose a coherent direction: content hierarchy, typography, palette, layout rhythm, image/art treatment and purposeful interaction. Explain how these express this product. If the user delegates, compare candidates internally and present the selected direction; render alternatives only when they want to choose.
3. Implement one representative screen or section at phone and desktop widths before repeating its patterns. Reuse project tokens/components across pages. A reference guides principles, not copying another site's branding, protected assets or exact layout.
4. Review the rendered result: can a visitor identify the product, primary action and useful evidence quickly? Do imagery, copy and layout convey something specific? Is every element earning its space? Remove filler and decorative complexity that weakens the task.
5. Apply the chosen final polish pass after substantial visual work, then check contrast, keyboard/focus, reduced motion and responsive states. A source-code detector is a hint; screenshots and working interaction are necessary evidence. If no browser is available, label the visual result unverified.

Generic patterns are warning signs, not forbidden technologies. Gradients, cards, rounded corners and familiar navigation can be appropriate when justified by content and user needs. Swapping purple for green does not create art direction. Do not substitute elaborate motion, 3D or unusual fonts for usability. Do not fabricate customers, ratings, testimonials, metrics or awards. Use licensed assets, real supplied content or clearly marked draft placeholders; no unresolved placeholders in a claimed launch-ready critical path.

For a specific missing reference or token-tooling need, [more skills](more-skills.md#additional-on-demand-capabilities-reviewed-2026-10-31) includes Awesome DESIGN.md and Google's optional format/tooling. Read one relevant source; keep the project's existing design record.

Copied components must match the same tokens, accessibility and performance requirements. Consult [component sources](component-sources.md) only for an actual component need. One suitable specialist beats combining competing design engines.
