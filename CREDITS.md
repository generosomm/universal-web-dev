# Community credits and dependency provenance

This wrapper coordinates independently published community skills. The wrapper's MIT license covers its original files only. It does not replace, relicense, or claim authorship of upstream skills, reference data, templates, scripts, fonts, images, services, binaries, or third-party material.

The lock records exact 40-character Git commit revisions verified against primary GitHub repository trees and raw source files on 2026-10-20. These are reproducible source snapshots, not a claim that every source is the newest release. No upstream skill files are bundled in this wrapper. The installer must preserve each selected folder in full and retain every listed license/notice file. Source entrypoints, resource trees and license files were inspected; no upstream code was executed.

## Installation completeness and compatibility

- Superpowers: 14 of the 15 `skills/*` folders are selected together; `diagnosing-superpowers` is omitted because no sibling references it. Preserve their adjacent canonical names and all nested scripts, references, templates and assets. `executing-plans`, `subagent-driven-development` and `writing-skills` reference sibling folders. A single copied SKILL.md is incomplete. The visual companion optionally reads repository version metadata outside its folder and safely falls back to `unknown`; this does not require copying repository manifests.
- Ponytail, Caveman and Emil: select only the named skill folders. Caveman's current pinned repository is Apache-2.0, with MIT notices retained for older contributions. This selection excludes all runtime engines, proxies, gateways, binaries, extensions, cloud routing and installation machinery. It makes no token-savings promise and does not activate its communication style unless the user requests it.
- Anthropic frontend-design: the public upstream skill is compatible guidance, not a guarantee of exact equivalence to a locally customized `frontend-design` copy. Its per-skill Apache license is verified independently of repository-wide metadata.
- Taste: source folder `skills/taste-skill` declares the canonical skill name `design-taste-frontend`. Preserve the complete `references/`, `assets/`, `scripts/` and `library/` trees. The current draw script explicitly supports an absent optional `library/scenes.json` using an empty scene library. Image and font catalog entries are references, not grants to redistribute third-party media. Scripts may use a locally installed browser when explicitly invoked later; dependency installation does not run them.
- UI/UX Pro Max: the pinned `.claude/skills/ui-ux-pro-max` tree contains real directories for `scripts/`, `data/` and `references/`; none of those selected paths is a symlink. No `src/` support remapping is necessary at this revision. Upstream examples reference `${CLAUDE_PLUGIN_ROOT}/.claude/skills/ui-ux-pro-max/scripts/search.py`; resolve those examples against the actual installed skill base directory as `<skill-base-dir>/scripts/search.py` without changing the user's machine configuration or altering upstream files. Retain `data/data-provenance.json`, `data/google-font-licenses.json` and other catalog provenance. Referenced fonts/icons keep their own terms.
- Impeccable: the current Codex distribution is `.agents/skills/impeccable`, including `reference/`, `agents/` and `scripts/`. The launchers require a separate release binary which they download on first execution if absent. The source commit lock does not pin that binary. Accordingly the installer copies `SKILL.md`, `reference/` and `agents/` but excludes `scripts/`, and records the exclusion in `UPSTREAM-NOTICE.txt`. No launcher or binary is executed or downloaded. The upstream documented launcher-unavailable fallback reads existing project context directly and continues with reference playbooks; live mode, the detector and pin shortcuts still need the upstream launcher, configured separately. `NOTICE.md` credits ehmo's MIT platform-design-skills for derived iOS and Android references.
- Backend profile: API Design retains its `references/` and `assets/` directories; OpenAI security guidance retains all its language/framework `references/`, agents metadata and per-skill license. Security review triggers still require an explicit user request.
- Postgres profile: Supabase's complete Postgres skill directory includes `references/` and its changelog. This does not install a database or connect to a Supabase project.

No selected automatic folder requires resources outside its own tree except the explicitly co-installed Superpowers skill siblings and the package-level license/notice files. There are no `support` remaps in this lock because the verified selected trees already contain their required data. Excluded paths are not counted as installed capabilities. All upstream instructions remain subordinate to the user's request and the host's higher-priority rules.

## Referenced, not installed

- [lucide-animated](https://github.com/pqoqubbw/icons) by pqoqubbw (MIT): animated Lucide icons for React. Its agent skill is generated by its website rather than stored as a pinnable folder, so it is not in the lock. references/component-sources.md only points React and Next.js projects to its shadcn registry (`https://lucide-animated.com/r/<icon-name>.json`), which adds one component file and the `motion` package to the developer's project when they choose to use it. The components ship without a reduced-motion fallback, so the component sources reference asks for one.
- [FeralUI](https://feralui.dev) by Sarthak Navalekar ([mortspace](https://github.com/mortspace)): playful, physics-driven React components. Each piece is its own repository; `pullcord`, `playcaptcha`, `feral-blob` and `feral-fur` are MIT on npm, and `stamp` and `liquid-glass-tip` are MIT repositories copied from source. DeskFolio and AniMaps have no license and are not recommended for copying. Nothing is installed or pinned by this skill.
